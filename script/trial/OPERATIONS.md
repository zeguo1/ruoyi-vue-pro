# MGS 试用开户候选版本操作说明

本候选版本仍未部署；未创建真实栖云租户、用户或业务记录。完整的官网—公众号体验链路尚未验收，不能开启公网试用申请。本文的执行步骤用于后续 MGS 发布，不代表已经执行。

## 职责与入口

双系统开户由 `TrialOrchestrator` 编排。知办服务端提供已验证的申请人身份、确认凭据，以及内部成员、个人授权、安全卡片、绑定和撤销能力。Agent 只能使用四个受限业务工具；初始化企业租户、选择菜单和配置密钥不是访客工具参数。

租户 `1` 是既有演示租户。新体验账号共享租户，但通过专属接口、实际客户所有权、CRM 权限和申请状态隔离。栖云是独立企业运营租户，真实线索仅存于栖云。首次体验不选择套餐；底层 `TenantService` 创建企业租户仍需要内部菜单权限快照，初始化任务会生成该技术记录，不展示给访客。

## 发布前核对

1. 在隔离环境运行 `bash script/trial/run-tests.sh`，登录/OAuth 原有回归另运行 `python3 script/trial/run-auth-regression.py`。新业务集成测试包含真实 Spring MVC、令牌/租户过滤器、方法权限、CRM 权限切面、客户/跟进/数据权限服务及 MyBatis；OAuth 校验、系统权限目录、字典、用户目录和其他业务服务仍有测试替身。H2 不是生产 MySQL。
2. 核对配置示例中所有 `null`：实际 HTTPS 地址、试用期限/配额、专用 OAuth 客户端、服务密钥、企业初始化联系人/容量/有效期及菜单。不要从模型参数取得这些配置。
3. 知办实现并共同验证 `KNOWDO_CONTRACT_DRAFT.md` 的内部接口、可信身份和安全卡片。尚未找到对方可联调实现；不得仅凭 adapter 测试开启申请。
4. **MGS 私有登录交付已实现，知办安全卡片和实际浏览器登录仍待联调**。普通账号密码仅加密保存并通过 DELIVERY 服务签名接口交付原主体，个人业务 OAuth 交换不等同于浏览器登录。新增 `login-delivery` 加密密钥配置缺失时关闭新申请；不要将密钥或私有响应交给模型。
5. 按 MGS 自身发布规程准备单独构建目录、备份与回滚制品。现有运行实例绑定了 `yudao-server/target/yudao-server.jar` 和 `web-antd/dist`；不要在开发工作树运行打包或前端 build 覆盖这些挂载。

## 增量迁移与开启存储

在备份后按顺序审阅并应用 `V20260914_01__trial_onboarding.sql`、`V20260914_02__trial_menus.sql`、`V20260914_03__trial_operator_setup.sql`、`V20260914_04__trial_login_delivery.sql`。它们新增状态、菜单、初始化登记和加密登录交付，不重新导入基础数据库。菜单迁移不替既有用户授予权限。设置独立的 AES-256 加密版本密钥，并保留仍有有效交付记录所需的旧版本密钥。

迁移和候选制品发布后才可设置 `mgs.trial.storage-enabled=true`。保持 `mgs.trial.enabled=false`，此时新增申请关闭，已有记录仍能查询、维护和撤销。已发布实例需验证实际 `/v3/api-docs/all`；当前 `generated/openapi.json` 是隔离 Springdoc 导出的候选文档，不是运行服务的导出。

## 栖云内部初始化

处理器名为 `trialOperatorBootstrapJob`，参数必须为 `initialize-qiyun`。复用基础设施任务管理，仅内部授权运维账号拥有 `infra:job:create/update/trigger` 权限；不得授予体验角色，不导入官网客服工具目录。

1. 在受控部署配置中填写 `mgs.trial.operator-bootstrap`，初始密码从密钥存储注入。提供已审阅的企业菜单 ID 和全部祖先；必需包含 `crm:trial:query`、`crm:trial:recover`、`crm:clue:query`。其他企业业务菜单按企业实际范围配置，不机械复制给体验角色。此步骤保持初始化开关关闭。
2. 通过现有 `POST /admin-api/infra/job/create` 登记处理器。该接口创建时立即安排 Quartz 调度，所以使用经运维确认的未来触发时间，随即通过 `PUT /admin-api/infra/job/update-status?id=<真实任务ID>&status=2` 暂停，避免自动执行。不要把密码放入任务参数或任务备注。
3. 配置确认后，在 MGS 正常发布流程中临时打开 `operator-bootstrap.enabled`。用现有 `PUT /admin-api/infra/job/trigger?id=<真实任务ID>` 手动执行一次，并检查实际任务日志。触发接口 `code=0` 仅代表触发受理，不能当作初始化完成。
4. 任务完成结果只返回 `operator-tenant-id`、`owner-user-id` 和内部权限快照编号；用真实结果填写运营配置。内部管理员是企业账号，既不作为演示账号交付，也不会替换租户 `1`。确认其 CRM 负责人有效、运营页面和所需业务权限可用。
5. 执行后关闭 `operator-bootstrap.enabled` 并保留暂停的初始化任务。重复执行只核对原资源，不重设管理员密码、不覆盖角色。配置不一致、已存在同名栖云但没有初始化登记、资源被删除/替换时会返回错误，留给内部管理员核验；不得清空登记表来强行重跑。

实现用现有 `@DSTransactional` 包围内部权限记录、租户创建和初始化登记，数据库 guard 行防并发重复。隔离 H2 测试现已使用实际 Tenant/Package/Menu/AdminUser/Role/Permission 服务，验证并发幂等、内部管理员与普通演示账号隔离，以及最后登记失败时真实资源共同回滚。部门/岗位/配置/MQ/CRM/OAuth 仍是外围替身；发布环境 MySQL 初始化尚未执行。

## 持续开户与到期维护

`trialMaintenanceJob` 是已有 Quartz 的普通全局任务，不能加 `@TenantJob`。通过现有任务管理登记，建议每分钟检查一次，处理器参数留空；实际周期由部署方确认。每批最多检查 20 个待处理申请，生产仍需观察延迟和队列长度。申请状态接口不会触发写入，运营“恢复”只重新排队，不跳过用户确认。

先在隔离环境验证双侧接口，再逐步开启新申请。申请必须全部步骤完成、且未到期才是 `accountReady=true`；绑定成功和首次真实业务完成分别记录。两侧撤权都完成后才是 `EXPIRED`。单侧失败继续维护，不重建已成功账号，不因消息发送失败重新开户。

## 回滚与关闭

- 先关闭 `mgs.trial.enabled`，暂停新申请；保持存储功能和维护任务运行，让既有申请完成撤权或保持可恢复状态。
- 保留申请、步骤、账号映射、业务幂等记录、授权引用、企业初始化登记和 CRM 数据。不要删除普通账号来代替撤销会话，不清空租户 `1`。
- **存在活跃试用账号时，不能直接回滚到不含 `TrialBusinessAccess` 的旧制品或关闭 `storage-enabled`。** 原版本不具备共享演示租户的专属接口限制。先验证两侧权限、既有令牌和渠道业务能力全部撤销；无法完成时，保留带访问保护的维护版本，禁止恢复不带保护的旧版本。
- 制品切换、数据库备份和健康检查按 MGS 发布流程执行；不要重启共享入口、隧道或知办。运行文档、前端和工具契约都需版本核对，知办同步由知办任务完成。
